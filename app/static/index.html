How an answer is built

  1. Ingest. Text and metadata come out of PDF, DOCX, HTML, and plain-text files. Two chunkers run: sentence packing and a fixed window. Exact SHA-256 duplicates and near duplicates (simhash within Hamming distance 3) are not indexed twice.
  2. Index. Chunks are embedded with MiniLM and stored in Chroma. A separate Okapi BM25 index, written for this project, handles keywords.
  3. Rank. Evidence Coverage Rank Fusion is our ranker. It fuses the two lists with reciprocal rank, adds a coverage bonus, penalizes near-duplicate chunks, and prefers evidence from more than one document.
  4. Investigate. The agent calls search_evidence, follows bridge entities for a second hop, and calls detect_contradictions. The model may request one more tool call.
  5. Answer. The draft must cite chunk ids from that evidence. Uncited claims and invented numbers are dropped. Thin or conflicting evidence is labeled, not papered over.
